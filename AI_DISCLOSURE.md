# AI Disclosure

This project uses AI in three distinct roles. Each one is listed below with where it
appears in the repository.

## 1. Inside the product

| Where | Model | What it does | When |
|---|---|---|---|
| Live path (`engine/cold.py`) | `qwen2.5:1.5b` (Alibaba Qwen, 4-bit), run locally through Ollama | Picks step *numbers* from the supplied support article and names the screens it needs. It never writes the step text or a deeplink (ADR-001, ADR-002). | Per request, only when an unseen article is supplied |
| Semantic cache and retriever (`engine/embed.py`, `engine/cache.py`, `engine/deeplink.py`) | `BAAI/bge-small-en-v1.5` sentence embeddings, on the CPU | Matches complaints to cached plans and screen descriptions to catalog entries | Per request |
| Build tier (`build/skeletons.json`) | Anthropic Claude Opus 5 | Ran the same pipeline once per supplied article: chose step numbers, grouped them into actions, and wrote the action names, screen descriptions and the cached phrasings of each plan. `scripts/compile_plans.py` validates that captured output through gates G0–G16 before it becomes `artifacts/`. | Once, offline. No hosted model is called at runtime. |

No response text is generated freely by a model. Steps are copied verbatim from the
source article, and deeplinks are copied from the supplied catalog.

## 2. Building the project

The team developed the project with **Claude Code** (Anthropic's coding assistant,
Claude Opus models) as a pair programmer. The team directed the work and made the
product decisions. Claude Code wrote much of the code, tests, evaluation scripts and
documentation. Commits do not carry per-commit AI attribution; this document is the
disclosure, and it covers the whole repository.

AI assistance also produced:

- the evaluation fixtures in `tests/fixtures/`: labelled deeplink screens, paraphrase
  and out-of-scope test sets, and the battery, camera and performance probe articles
  in `tests/fixtures/probes/` (synthetic, never compiled into the cache)
- the benchmark runs and `reports/`, generated by the scripts in `scripts/`
- this repository's README, the documents in `docs/`, the presentation in
  `presentation/`, and the demo-page screenshot
- the demo video. It is a screen recording of the real system, the actual API
  and a local model answering live, driven through the demo scenes by a script
  (Playwright controlling headless Edge). The on-screen captions were written with
  Claude Code, and every number in them comes from `reports/`.

## 3. Evaluation

The scores in `docs/metrics.md` are computed mechanically by `scripts/` against the
rubric in `docs/RUBRIC.md` and the labelled fixtures. No model acts as a judge. Every
figure can be regenerated with `python scripts/run_reports.py`.

## Data

The support articles, deeplink catalog, queries and response schema come from the
hackathon's Theme 02 kit. No user data is collected. The product makes no network
calls at runtime except to the local Ollama server.
