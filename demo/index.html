How it works

      
    
        
  1. Semantic cache. Known issues return a pre-validated plan with no model call.
    2. 
        
  2. Live plan. A new issue plus its article goes to a small local model that only
            selects steps from the article — it never writes them.
    3. 
        
  3. Deeplinks. Each settings step is matched to a real catalog screen; the model
            never sees or writes a URI.
    4. 
        
  4. Gates. Every response is schema-checked and scrubbed of web links before it leaves.
